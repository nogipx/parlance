# Протечки: как проверяется, что обещания держатся

Протечка — место, где обещание библиотеки не выполняется, и вызывающему приходится знать, что внутри. Каждая найденная протечка кончается одним из трёх: код держит обещание, обещание сужено (имя, тип, документация говорят правду), или деталь выведена наружу (статус, ошибка, флаг).

## Что считается обещанием

Только то, что экспортируют `app.dart` и `schema.dart`. `tools.dart` и `testing.dart` ничего не обещают (`Host`: «promises nothing»). Обещание члена — это его документация, его тип и поведение, на которое уже опираются вызывающие.

## Оси

Каждое обещание проверяется по осям; где оси расходятся, там протечка.

- **Где.** Владелец в процессе хоста или по сети; тот, кто пользуется словами, — там же или по сети. Четыре сочетания, одно ожидание: `test/contract/where_test.dart` гоняет каждый сценарий во всех четырёх.
- **Когда.** До подключения, подключён, во время обрыва связи, после снятия владельца или `dispose` участника.
- **Чем кончилось.** `done`, `refused`, `failed`, `timedOut`, `cancelled`, `lost`: что каждое значит для того, было ли действие, и что делает повтор по id.
- **Повтор.** Тот же id во время первого вызова, после обрыва, после позднего конца, после отмены до старта.

## Вопросы к каждому обещанию

Таймаут, отмена или ошибка — значит «не было», или работа идёт дальше? Может ли вернуться правдоподобное значение по умолчанию вместо ошибки? Значит ли `null` или пустое несколько разных вещей? Видно ли чтение сразу после записи? Одинаково ли ведут себя локальная и удалённая реализации? Узнаёт ли вызывающий, что упёрся в предел? Что бывает при вызове после `dispose`?

## Что считается доказательством

Строка кода, на которой видно расхождение. Если оно зависит от поведения чужой библиотеки — её исходник (так было с rpc_dart, который отменяет серверный токен при закрытии канала). После исправления — тест, который падает на старом коде и проходит на новом. Протечка, которую решили не чинить сразу, остаётся в наборе пропущенным тестом со ссылкой сюда.

## Карта поверхности

Строится из кода: `fvm dart run tool/surface_map.dart` из корня репозитория пишет `docs/карта-поверхности.md` — каждое имя и член `schema.dart` и `app.dart` и тесты, что на них ссылаются; сначала то, на что не ссылается ни один тест. Файл в git не хранится (`.gitignore`) и переписывается при каждом запуске, так что не устаревает незаметно: перед проходом его пересобирают и читают.

Анализатор разбирает тесты и сопоставляет разрешённые ссылки с элементами поверхности, а не текст: аргумент аннотации засчитывается полю, геттер — полю, реэкспорт `app.dart` — один раз, неявные члены (`values` у enum, неявный конструктор) и члены чужих типов (`LogScope`) не считаются. Имя засчитывается и через его члены (у расширения `OwnerTools` по имени не ссылаются). Метка `where` — ссылается `where_test`, то есть проверено во всех четырёх сочетаниях; `generated only` — ссылается только сгенерированный код. Ссылка из теста — не доказательство, что обещание держится; её отсутствие — точно непроверенное. Та же поверхность, что сверяет `tool/frozen.dart` с последним тегом (`tool/surface.dart`).

## Обещания по поведению

`where`: проверено во всех четырёх сочетаниях `where_test.dart`. Остальное — файлы `test/`.

| Член | Обещание | Где проверено |
|---|---|---|
| `Host.participant` | участник части в процессе хоста, словари одного владельца | `contract/host`, `participant/participant` |
| `Host.serve`, `IRemoteSession` | сессия гостя: права, пределы, конец с соединением или `dispose` | `remote/session`, `remote/session_limits`, `remote/ended`, `remote/takeover` |
| `Host.join` | гость, переподключается, отказ при другом протоколе | `participant/remote_participant`, `remote/features` |
| `Host.dispose` | всё уходит, последний созданный первым | `registry/dispose` |
| `IParticipant.batch` | целиком или никак, и копии владельца тоже | `participant/batch_whole` (здесь и по сети), `where` |
| `IParticipant.settle` | всё попрошенное сделано; после `dispose` — сразу | `remote/settle`, `remote/feed_gaps`, `where` |
| `IParticipant.dispose` | владельцы и слова уходят; ушедший отказывает | `where` |
| `IRemoteParticipant.attach` | всё или ничего, как в процессе хоста | `participant/remote_participant` |
| `IRemoteParticipant.errors` | что хост отказал; потерянные факты (`factsLost`) | `remote/feed_gaps`, `remote/session_limits` |
| `IStateOf.value`, `changes` | значение сейчас, затем изменения; по сети без подписки тоже | `where` |
| `IKeyedOf.of`, `all`, `keys` | одно чтение на все; нечитаемое пропущено | `participant/keyed_read`, `where` |
| `IFactOf.facts`, `recent` | факты с момента подписки; прошлые по запросу | `where`, `remote/feed_gaps` |
| команда клиента | значение или `CallNotDone` с причиной | `where` |
| `cancel:` и `CancellationToken` | отмена ожидания; до старта — не запускается | `participant/cancel`, `where` |
| повтор по id | выполняется один раз; ждёт позднего конца | `participant/cancel`, `contract/contract`, `where` |
| `CallLost` | ответа нет, выполнено ли — неизвестно | `participant/remote_participant` |
| охранник (`guard`) | отказ `denied` с id охранника | `owners/owner_tools_more`, `where` |
| `OwnerTools.by`, `expired` | от чьего имени вызов; токен вызова | `owners/answering`, `participant/cancel`, `where` |
| `OwnerTools.once` | факт под тем же id слышен один раз | `where` |
| `OwnerTools.follow`, `listen`, `hear` | пока подключён; после снятия — явная ошибка | `owners/owner_tools`, `owners/hear` |
| `OwnerTools.now` | часы участника | `participant/keyed_read` |
| `Single`, `Keyed` | что записано и принято реестром | `participant/batch_whole`, `where` |
| снятый владелец | пишет в никуда, говорит, что снят | `participant/remote_participant`, `where` |
| `WordStatus` | слово есть, нет, недоступно, не то | `registry/word_status`, `participant/mismatch`, `where` |
| формы и типы | проверка значений, JSON туда и обратно | `registry/types`, `registry/shape`, `registry/json_shape` |
| совместимость слов | разрывы между версиями | `schema/schema_breaks`, `registry/compat` |

## Открытые протечки

- **J1–J4** (`parlance_journal`). Писатель журнала по умолчанию молча глотает ошибки записи; сводки разговора не знают `cancelled` и `lost`; читатель молча пропускает строки новых видов; «как бы ни остановилось приложение» — без `fsync`.
