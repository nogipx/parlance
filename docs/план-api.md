# План: замороженное API без церемоний

Цель: то, к чему прикасается разработчик, замораживается навсегда («не ломать, только добавлять»), а внутренности библиотеки остаются свободными для улучшений. И разработчик не пишет того, что библиотека может сделать сама.

Три контракта:
- **разработчика** — аннотации и лицо сгенерированного кода (база владельца, клиент);
- **хоста** — то, что вызывает `main`;
- **генератора** — всё из parlance, на что ссылается `.g.dart` (пакет слов публикуется со своим `.g.dart`).

## А. Форма (решить до заморозки) — сделано

1. **Причина через Zone.** Обработчик команды выполняется в Zone с вызовом; запись, факт и вызов без `cause` внутри него (и после `await`) следуют из этого вызова сами. Работает для любого владельца, рукописного и сгенерированного, в процессе и через соединение.
2. **Чистый владелец — одна сгенерированная база:**
   - обработчики с обычными именованными параметрами, без `CommandCallOf`;
   - состояния — сеттеры и геттеры, факты — методы без `cause`;
   - `whyNotX()` для доступности;
   - без реестра владелец хранит значения у себя, сказанные факты — в `said` (для тестов).
3. **Без своей копии и `sync()`.** Библиотека помнит последние записанные значения и сама отправляет их заново после переподключения; `sync()` необязателен, только для владельца, чьё состояние выводится из чужой модели.
4. **Кто вызвал.** `@CommandWord(caller: true)` даёт обработчику параметр `String caller`.
5. **Выход из причины** для действий владельца, которые не следуют из вызова (таймер, заведённый в обработчике).
6. **Пакет записей вне обработчика**, если понадобится.
7. **Подключение спрятано:** `define` приватный, разработчик видит у владельца только свои слова и обработчики.
8. **Клиент** (`XClient`/`IXClient`) — проверить на тех же принципах.
9. **Sealed-семейства** (`CallResult` и подобные): решить, может ли семейство вырасти; если да — сразу вариант «другое».

## Б. Без церемоний — сделано

10. **Несовпадения слов сообщаются сами:** участник отдаёт их в свой поток ошибок и печатает в разработке; ручная подписка — только для иной реакции.
11. **`attach` возвращает Future**, который завершается, когда хост принял слова; `await p.flush()` после него не нужен.
12. **Явное ожидание в тестах:** `await p.settle()` — пока копия не догонит то, что записали вызовы, вместо задержки.
13. **`Registry.dispose()` закрывает сессии и участников сам.**
14. **Сессия закрывается сама, когда рвётся соединение** (нужен сигнал закрытия точки в rpc_dart).
15. **Примеры не учат лишнему:** убрать `List.of` перед записью и прочие копии.

## Что вышло в А и Б (2026-10-29)

- Причина через Zone: обработчик и `hear` идут в зоне того, на что отвечают; явная причина главнее (3512aa1).
- Владелец: обработчики с параметрами команды, состояния — сеттеры и геттеры, с ключом — `Keyed<T>` (`light[room] = on`), факты — методы с `by:`, без реестра — свой тестовый двойник (`said`) (d677277).
- `caller`, `apart`, `together` у `Owner` (d17c9e2); `CallResult` замораживается как есть.
- Несовпадения слов гость сообщает сам, ошибкой `mismatch` (b1c9a68).
- `await p.attach(...)`; `settle()` ждёт копию, слушателей и синхронизации владельцев (9ac33cc, e36bd34).
- `Registry.dispose()` закрывает участников и сессии; запись ушедшего участника молча отбрасывается (c44d046).
- Сессия закрывается сама, когда кончается транспорт; rpc_dart дорабатывать не пришлось (b369953).

## В. Три контракта — сделано

16. **`package:parlance/schema.dart`** — аннотации и типы из сигнатур сгенерированного кода; больше ничего.
17. **Библиотека хоста `app.dart`** — `Registry`, `participant`, `attach`, `serve`, `SessionLimits`, `WordSet`, права.
18. **Контракт генератора:** интерфейсы для поведения (`IParticipant`, `IStateWriterOf<T>`, `IFactEmitterOf<T>`, `IOwner` без членов вместо базового класса `Owner`), константные классы для описания слов, sealed-классы для результатов.
19. **Всё остальное** (сырой API реестра, сессии, зеркало) — внутреннее, без обещаний.

## Г. Правила — сделано

20. **Только добавлять:** новая аннотация, необязательный параметр, сгенерированный метод, форма; не переименовывать, не удалять, не делать обязательным, не менять смысл.
21. **Поведение замораживается тоже** — тесты-контракты: один вызов обработчика на id, запись равного значения не изменение, пакет — всё или ничего, отказ говорит причину.
22. **Старый `.g.dart` компилируется с новой библиотекой.**

## Тонкая база владельца (2026-10-29)

- Сгенерированная база реализует `IOwner` — интерфейс без членов. В классе разработчика только его слова, обработчики и `said`; приватные имена базы начинаются с `_$`.
- Всё, что владелец делает с библиотекой, — расширение `OwnerTools`: `follow(pull, on:)`, `listen`, `hear`, `choices`, `onDispose`, `whenAttached`, `participant`, `caller`, `apart`, `together`. Своё имя владельца главнее расширения, поэтому новый помощник ничего не ломает.
- Переопределять нечего, кроме обработчиков: `sync`, `changes`, `dispose`, `defineMore` заменены вызовами в конструкторе.
- Ручной `Owner` с `define`/`sync` остался в `participant.dart` для тестов и инструментов, вне замороженных библиотек.
- `tool/frozen.dart` считает поломкой и добавленный член у того, что реализует приложение или сгенерированный код (`IOwner`, семейство `IWord`).

## Роли вместо классов (2026-10-29)

Замораживается то, что нужно ролям (владелец, потребитель, `main` хоста и гостя, тесты), а не конкретные классы с их полным API.

- `IParticipant` в `schema.dart` узкий: `who`, `child`, `attach`, `sync`, `settle`, `batch`, `dispose`, чтение и вызовы, типизированные слова через `serve`. Всё по имени и дескриптору — `IRawParticipant` в `participant.dart` (`p.raw`), без обещаний.
- `OwnerTools`: типизированный `guard`, `now`, доступность перепроверяется сама после `follow`/`listen`/`hear`; `StateWordOf`/`FactWordOf` для слов с именами во время работы; `failCall` в `schema.dart`.
- `app.dart`: `Host` (final class: `participant`, `serve` → `IRemoteSession`, `alias`, `registerType`, `dispose`, `registry` для инструментов), `HostBounds`, `Host.join`/`Host.over` → `IRemoteParticipant`. Конкретные `Registry`, `LocalParticipant`, `RemoteParticipant`, `RemoteSession` ушли из замороженной части.
- Правило: расти может то, что создаёт только библиотека (final-классы, интерфейсы, которые не реализуют приложения); не растёт то, что реализует приложение (`IOwner`, `IWord`).
- Типы `rpc_dart` в сигнатурах `Host.serve` и `Guest` приняты как часть контракта.

## Один путь (2026-10-30)

У каждого дела один способ (философия, «Один путь»). Что делало то же другим путём, ушло в инструменты или удалено:

- У `IParticipant` нет ни чтения и вызовов по имени, ни типизированных слов: часть пользуется клиентом `<Class>Client(participant)`, владелец — своей базой. Сгенерированный код обращается к словам через одну дверь, `GeneratedWords.of(participant)` в `schema.dart`.
- Ручной `Owner` — только для тестов пакета, не экспортируется. `StateWordOf`/`FactWordOf` ушли из `schema.dart` в инструменты.
- `host.serve` убран: участник всегда `host.participant(...)`, затем `.attach({...})` здесь или `.serve(endpoint)` через соединение. `TestHost` построен на `Host`, его гости входят через `Host.join`.
- `OwnerTools.guardAll(id, (command, by) => why)` — правило владельца на все команды его участника, без сырого `addGuard`.
- Библиотеки: `schema.dart` и `app.dart` (заморожены), `testing.dart`, и одна незамороженная `tools.dart` вместо `registry`, `participant`, `remote` и `view`.
