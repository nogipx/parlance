# parlance

A registry of **states** (one owner writes, everyone reads), **commands** (one handler, a params schema, who may call) and **facts** (what happened). **A state is written by its owner only; a command asks the owner.** The registry holds no relation between a command and the states its handler writes: what a handler does is its owner's business, and what it did is told after, by causes. Participants know only the catalog, never each other; `main` wires them.

The contract the code and its tests follow is in `references/`, one file per library; read only the one a task needs. `SPEC §n` in the code is section n there. Where code and contract disagree, the contract is fixed first, then the code. Version 0.1 (draft).

## Adding to the registry

A host names its words once, typed (SPEC §18), and never types a name or a param key elsewhere:
- **Words, generated:** write them once as an abstract class marked `@Vocabulary('orders')` (`package:parlance/schema.dart`, frozen, all a words package and an owner see; `main` imports `package:parlance/app.dart`, frozen too), members marked `@StateWord`, `@CommandWord`, `@QueryWord`, `@FactWord`, bounds by `@Range`, `@Length`, `@ChoiceOf`, an enum's fallback by `@Fallback()` on one value (SPEC §25.2); `parlance_generator` makes the enums below, the params records, the vocabulary `<class>Words` (a `WordSet`: its name and words; `main` grants it, `host.participant(who, vocabularies: [ordersWords])`, so its name is written once) and the owner base `<Class>OwnerBase`: extend it and write only the handlers, of the class's own params (`void setVolume({required int volume})`); states are fields it sets (`volume = 95`; keyed, `light[room] = on`), kept by the base and written once attached, so no copy and no `sync()` of its own; facts are methods of their params (`clipped(volume: 95)`, `rang(who:, by: visitor)` for another); what a handler does follows from its call, no cause written; not attached, it keeps what it set and `said`, its own test double; every word is named in its vocabulary (`orders.cancel` in `orders`), and a vocabulary is one owner's; `callers`, `available` and the rest are said in the annotations (SPEC §23.4). A consumer takes the interface `I<Class>Client` (a test gives a stand-in), and `main` gives it `<Class>Client(view)`: states as getters and `...Changes` streams, commands and queries as methods of the class's params that throw `CallNotDone` (an `Exception`) when not done, facts as streams of their payloads; the interface says no parlance type, and the client alone adds `status` and `<fact>Facts` (the `Fact<T>` with its message, for an owner to follow from) (SPEC §23.5). Before a release, hold the words to what is out: `breaksSince(releases, schemaOf(ordersWords.words))` empty, the releases' schemas taken from their tags, pub or a registry of frozen versions, not from a file kept in the repository (SPEC §25.3).
- **Words:** an enum per owner, `enum XState<T> implements IStateWord<T>`, `enum XCommand<P, R> implements ICommandWord<P, R>`, `enum XFact<T> implements IFactWord<T>`; each value its name and shape. Params and objects are records with a `RecordShape(fields, to:, from:, get:)`; enums are `EnumShape(values, unknown:)`; no params is `RecordShape.none`. A word a typed owner in this process defines is kept as its Dart value, held to its JSON's rule by its shape; JSON is made only at the edges (by name, across a connection, the journal), so in this process read, hear and call through the typed handles, never by name (SPEC §18).
- **Owner:** a class that extends its generated base (`IOwner`, no members of the library's), code only; `main` makes a `Host` (`app.dart`) and the participant (`host.participant(who, vocabularies: [ordersWords], rights:, access:)`, a narrow `IParticipant`; the raw one, `p.raw`, is the library's and its tools') and attaches the owners to it (`await p.attach({'devices': Home(), ...})`: each speaks as its part, `house@heating`, for audit). It overrides only its handlers; the rest it says in its constructor by `OwnerTools` (extensions, so its own names stay its own): `follow(pull, on: model.changed)` for states taken from a model of its own, `listen`, `hear`, `choices(kind, ...)` (for agents and editors), `guard(word, id, (params, by) => why)`, `now`, `onDispose`, `whenAttached((p) {...})` for words named at run time (`StateWordOf`); its commands' availability is asked again after what it follows or hears, unsaid; a port that says no ends the call with `failCall(why)`; `p.sync()` runs every owner's `follow` as one tick. A participant is a scope: made when a user signs in or a feature opens, disposed when it ends, its owners, words, values and kinds going with it (SPEC §19.2). An owner says nothing of the words of others it needs: it asks their status when it needs them (SPEC §19.1).
- **State:** `p.state(XState.a).define(meta:)` on the owner's participant returns the only `StateWriterOf<T>`, kept by the owner. Nobody else writes it: whoever wants it changed calls a command of the owner's, and the owner writes what comes of it.
- **Command:** `p.command(XCommand.b).define((c) => ..., callers:?, deadline:?, available:?)`; `callers` may be left to the participant's `access.call`; a word that only answers is a query, a kind of its own (SPEC §6.6, `QueryDescriptor`; `defineQuery` for names known at run time): `enum XQuery<P, R> implements IQueryWord<P, R>`, `p.query(XQuery.c).define((q) => ..., askers:?)`, asked with `.ask(params)` (no dedup or call record; askers default as readers); its handler gets a `QueryAsk`, and a write, fact or command call from it is refused (`QueryEffect`), so put nothing that changes the world in a query, not even past parlance; `c.params` is the record. `available` answers why it cannot run now (shown before anyone calls).
- **Fact:** `p.fact(XFact.c).define()`; `emit(record, cause:)`.
- **Call and read:** `p.command(XCommand.b).call(params)` answers `CallResult<R>`; `p.state(XState.a).read()`, `.watch()`; `p.fact(XFact.c).stream`; a screen does the same on its view. Never a generic helper taking a word and params together: it loses the types (SPEC §18).
- **Is a word there for me:** `view.status(word)` / `statusChanges(word)` (on a participant or a view): `WordMissing`, `WordNotPermitted`, `WordUnavailable(why)`, `WordReady` (SPEC §6.5); through a typed word or a client also `WordMismatch(breaks)`: the word is there but not as this code was built against (a module updated apart), by the rule of SPEC §25.1, as the data goes (what code reads it must read, what it gives the word must take), each break a `WordBreak` (`path`, `kind`, `was`, `now`, `certain`); `client.mismatches` / `wordMismatches(view, words)` lists them, to assert empty at start in development; a remote participant tells each one itself, as its error `mismatch`, nothing wired for it. The host sees the same of every part: a client made tells the registry what it was built against (`view.builtAgainst(words, from:)`, by fingerprint across a connection), and `registry.mismatches` / `mismatchChanges` say who meets which word otherwise and of which words package version, logged as a warning (SPEC §6.9); diagnostics, but for params a command no longer takes, left out of an old caller's calls (§25.5). Before release: `breaksSince(releases, now)`. An absent word never fails a read or a listener; ask its status instead of checking the catalog once at start.
- The string API on a participant (`defineState(StateDescriptor(...))`, `call(name, map)`) is for names known only at run time: a plugin's words, remote, MCP.
- **The registry acts for no one** (registry.md, the start): `main` makes it, makes participants and watches it (`explain`, `calls`, `usesOf`, `conversation`, `ticks`, `journal`); defining with `by:`, `call(by:)`, guards, batches and reads by name are the package's own (`RawRegistry`, not exported). A part is given a participant, never the registry.
- **Callers** decide who may call: selectors are `*` or `kind[/id][@owner]` (`user`, `module/visit`, `house@devices`, `module/orders@sync`); a selector names itself and its owners, a kind all of it, the nearest said wins; an id is one level of letters, digits, `.`, `-`, `_` only, all else reserved (a selector or principal with another sign is refused; make an id of an outside text with `Principal.levelOf`); unmatched is denied; `warn` allows but tells editors.
- **Causes:** inside a handler, what it writes, says and calls with no cause given follows from the call it serves, after an `await` too: the participant runs the handler in a zone that holds the call (a value in a zone, a fraction of a microsecond a call), so the trail shows which call led to it. A cause given wins. A timer the handler starts goes on in that zone, and so follows from the call too. A conversation (`cause.conversation`) is all that followed from one message, and `cause.origin` what it started with (the first message's `{word, by}`; `originOf(word)` for the first), given by the registry from the parent, never claimed: `registry.conversation(id)` (bounded, may forget); spans carry it. What must not be lost is the journal (SPEC §9.3): `registry.journal` tells every call begun and ended, fact said and write in a conversation, as it happens, with `conversation` and `trace`; the host writes it (`parlance_journal`).
- Names are lower-case words split by `.`, joined within by `_` or `-` (`house.door.left_open`, `kitten-daycare.lights`); never two owners for one name.

- **Who uses a word** (SPEC §6.8): `registry.usesOf(name)` / `usage` count the uses the compiler cannot see (calls by anyone, remote subscriptions, reads by sessions and agents), by the name used; check it before removing an old word or name.
- **Words are a public API.** Plugins, agents and what the host stores (a call kept in a project) name them. Never rename one bare: keep the old name with `registry.alias(old, now)` so what named it keeps working.

## Why a call was refused

Stages, first refusal wins (SPEC §9): dedup by id (`idConflict` if the id was given to another call) → command exists → params (`invalidParams`) → callers (`notPermitted`) → `available` (`unavailable`) → guards (`denied`, with the guard id) → handler (`failed`; `timedOut` means *no answer yet*, the work may still finish). `why`/`explain` and the call records (`calls`) tell what happened; `callStarts` and `running` what is in flight.

**Logs and telemetry** (SPEC §9.2): `Registry(log: controller.scope('parlance'))` logs a span per call (a nested call a child span, in one trace; across a connection too), refusals, ticks, the catalog and errors. Spans are kept whatever the level; log lines are by level, their messages constant and what varies in `data`. Without a log nothing is made. In a handler log with `call.span.event(...)` (an event that costs something to build behind `span.isEnabled(level)`; without a log the span is `noop`'s), never a logger found through a zone.

## Remote and agents

- A session's principal is fixed by the host when it accepts the connection; call ids are per principal. Both sides are `RpcPeerEndpoint`s. **The host serves a guest**: `host.serve(endpoint, who, vocabularies:, rights:, access:, limits:)`, the participant made as for a module in this process (a plugin's: `[WordSet.open(id)]`, its words come at run time), an `IGuestSession`: it ends by itself when the connection does (`ended`), the participant going with it (`close()` ends it sooner). Serve only a participant made for the session: one served already or used in this process is refused. Its access by default is the part's across too (SPEC §14, §22).
- **A remote part is a participant too:** `await Guest.join(connection)` (`RemoteParticipant.join` in tools), always over an `RpcClientConnection` (it rejoins after a drop; a fixed connection, wasm or memory, is one that does not reconnect), gives the same `IParticipant` as in the host's process, so an owner attaches to it unchanged (`await p.attach({...})`). What it asks goes in order, one turn as one tick; refusals come to `errors`; `flush()` waits for the host. It reads another's state only while it watches it.
- Over an endpoint a runtime hands it (a wasm or JavaScript guest), `RemoteParticipant.over(endpoint)`: the same participant, with nothing to rejoin over.
- **It is the only way across.** The wire, its client and the mirror are the package's own: a plugin, a phone, an agent each join as a participant. Its feed carries only what its listeners ask for, and what it reads by name (`fetch`), and the host knows what it hears (`session.hears`). `join` completes when its view is live.
- **Delivery** (SPEC §14.1): a state arrives as its value now, a fact at most once (`factsLost` past the retained ticks), a call once per id (`lost` may have run: retry with the id). A fact that must not be lost is a state its owner keeps until it is handled.
- Remote outcomes are data: `CallLost(id)` when the answer did not come back (retry with the id); `synced` false while disconnected.
- MCP tools are curated (`parlanceTools(participant)`: an agent is a participant, here or across a connection); a host adds its own and must call `McpSession.toolsChanged()` whenever its tools change.

## Rules of the package

- Imports go one way: `remote` and `owners` use `registry`; `participant` uses `registry` and the view interface (`view/view.dart`), never remote; `owners` use `participant` too; only `remote` and `testing` (its connection in memory) use rpc_dart, but for its logger (`package:rpc_dart/logger.dart`), which the registry logs to. Rules between states and commands (when this, call that) are the host's, built on this public API, not the package's. `test/boundaries_test.dart` holds this.
- No words of any domain in `lib/` (the boundary test bans them); the host's vocabulary stays in the host.
- Results are typed (`CallResult<R>`, `Explanation`); serialize at the edges.
- `contract.g.dart` is generated: change `contract.dart`, then `fvm dart run build_runner build`.
- A behavior change updates the contract in `references/` in the same change.

## Testing

- A module of a host is tested with `TestHost` (`package:parlance/testing.dart`, SPEC §24): its own participant, stand-ins for the words of others, what it wrote, said and called read back.
- Fixtures: `test/registry/fixture.dart` (`Fixture`, principals `user`, `agent`, `viewer`, `owner`).
- A whole host in miniature: `example/` (run `fvm dart run example/main.dart`); `test/example_test.dart` holds it to what it prints.
- Time: `fakeAsync(..., initialTime: DateTime(...))` whenever time matters; the registry reads time from its `clock`.
- Name tests after the promise they hold ("an id stands for one call").
- Run: `fvm dart test` in `packages/parlance` (four files at a time, `dart_test.yaml`), or only the files a change touches; `fvm dart analyze`.
