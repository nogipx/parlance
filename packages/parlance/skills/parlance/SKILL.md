# parlance

A registry of **states** (one owner writes, everyone reads), **commands** (one handler, a params schema, who may call) and **facts** (what happened). **A state is written by its owner only; a command asks the owner.** The registry holds no relation between a command and the states its handler writes: what a handler does is its owner's business, and what it did is told after, by causes. Participants know only the catalog, never each other; `main` wires them.

The contract the code and its tests follow is in `references/`, one file per library; read only the one a task needs. `SPEC §n` in the code is section n there. Where code and contract disagree, the contract is fixed first, then the code. Version 0.1 (draft).

## One way (docs/философия.md)

Each task has one way; what does the same another way is a tool's or gone.

- **Words:** an abstract class marked `@Vocabulary('orders')` (`package:parlance/schema.dart`), members marked `@StateWord`, `@CommandWord`, `@QueryWord`, `@FactWord`, bounds by `@Range`, `@Length`, `@ChoiceOf`, an enum's fallback by `@Fallback()` (SPEC §25.2); `callers`, `available` and the rest in the annotations (SPEC §23.4). `parlance_generator` makes the typed words, the params records, the vocabulary `ordersWords` (a `WordSet`, granted by `main`), the owner base `OrdersOwnerBase` and the client `OrdersClient` / `IOrdersClient`. Every word is named in its vocabulary (`orders.cancel` in `orders`), and a vocabulary is one owner's. Before a release: `breaksSince(releases, schemaOf(ordersWords.words))` empty, the releases' schemas taken from their tags or pub, not from a file kept in the repository (SPEC §25.3).
- **Owner:** `class Shop extends OrdersOwnerBase`, code only: the handlers, of the class's own params (`void cancel({required String id})`); states are objects of the base with methods: `total.set(95)`, `total.value`, `total.remove()` (a `Single<T>`); keyed, `line.set(id, qty)`, `line.of(id)`, `line.remove(id)` (a `Keyed<T>`); kept by the base and written once attached; facts are methods of their params (`placed(id: ...)`, `rang(who:, by: visitor)` for another, as far as the participant's `speakFor` lets it); what a handler does follows from its call, no cause written; not attached, it keeps what it set and `said`, its own test double. The rest it says in its constructor by `OwnerTools`: `follow(pull, on: model.changed)` for states taken from a model of its own, `listen`, `hear`, `choices(name, ...)` (for agents and editors), `guard(id, word, (params, by) => why)` for its command, `guardAll(id, (command, by) => why)` for every command of its participant, `once(id, say)`, `now`, `onDispose`; a port that says no ends the call with `failCall(why)`; its commands' availability is asked again after what it follows or hears, unsaid. An owner says nothing of the words of others it needs: it asks their status when it needs them (SPEC §19.1).
- **Using words:** a part takes `IOrdersClient` (a test gives a stand-in), and `main` gives it `OrdersClient(participant)`: states as getters and `...Changes` streams, commands and queries as methods of the class's params that throw `CallNotDone` when not done, facts as streams of their payloads; the interface has `status(word)`, `statusChanges` and `mismatches` too, and the client alone `<fact>Facts` (the `Fact<T>` with its message, for an owner to follow from) (SPEC §23.5). An owner that uses another's words makes their client in its constructor, `HouseClient.of(this)`: it finds the owner's participant when it is used, so `hear(HouseClient.of(this).rangFacts, ...)` is all it writes; read or called before the owner is attached, it throws a `StateError`.
- **Host:** `main` makes a `Host()` (`package:parlance/app.dart`; `HostBounds.light` for a small app that keeps nothing past now), then a participant per part, `host.participant(who, vocabularies: [ordersWords], rights:, access:)`, and either `await p.attach({'shop': Shop()})` (each owner speaks as its part, `shop@shop`) or `p.serve(endpoint, limits:)` for a guest across a connection, an `IRemoteSession` (`who`, `ended`, `close()`). A participant is a scope: made when a user signs in or a feature opens, disposed when it ends, its owners, words, values and choices going with it (SPEC §19.2). A part is given a participant, never the registry; `host.registry` is for tools.
- **Across a connection:** another process joins with `await Host.join(connection)` (rejoins after a drop) or `Host.over(endpoint)` (an endpoint its runtime hands it), an `IRemoteParticipant`: the same `IParticipant`, so an owner attaches to it unchanged; refusals come to `errors`.
- **Generated code** reaches the words through one door, `GeneratedWords.of(participant)`: the generator's contract, frozen with `schema.dart`, not a way to write by hand. A participant itself has no typed access to words and no reads or calls by name.
- **Is a word there for me:** `client.status(word)` / `statusChanges(word)`: `WordMissing`, `WordNotPermitted`, `WordUnavailable(why)`, `WordReady` (SPEC §6.5), or `WordMismatch(breaks)`: the word is there but not as this code was built against (a module updated apart), by the rule of SPEC §25.1, each break a `WordBreak` (`path`, `kind`, `was`, `now`, `certain`); `client.mismatches` lists them, to assert empty at start in development. The host sees the same of every part: a client made tells the registry what it was built against, and `registry.mismatches` / `mismatchChanges` say who meets which word otherwise (SPEC §6.9). An absent word never fails a read or a listener.

## Tools (`package:parlance/tools.dart`, not frozen)

- What tools do (an agent, a journal, an inspector, a host of guests in another language) is by name and descriptor: `p.raw` (`IRawParticipant`: `defineState(StateDescriptor(...))`, `call(name, map)`, `read`, `watch`, `fetch`, `addGuard`, `explain`, `describe`), words named at run time (`StateWordOf(name, shape)`, `FactWordOf`), the typed words on a raw participant (`p.raw.state(word)`), views (`LocalView`).
- **The registry acts for no one** (registry.md, the start): `main` makes it through `Host`, and tools watch it (`explain`, `calls`, `usesOf`, `conversation`, `ticks`, `journal`); defining with `by:`, `call(by:)`, guards, batches and reads by name are the package's own (`RawRegistry`, not exported).
- A word a typed owner in this process defines is kept as its Dart value, held to its JSON's rule by its shape; JSON is made only at the edges (by name, across a connection, the journal) (SPEC §18).
- **Callers** decide who may call: selectors are `*` or `kind[/id][@owner]` (`user`, `module/visit`, `house@devices`, `module/orders@sync`); a selector names itself and its owners, a kind all of it, the nearest said wins; an id is one level of letters, digits, `.`, `-`, `_` only, all else reserved (make an id of an outside text with `Principal.levelOf`); unmatched is denied; `warn` allows but tells editors.
- **Causes:** inside a handler, what it writes, says and calls follows from the call it serves, after an `await` too: the participant runs the handler in a zone that holds the call, so the trail shows which call led to it. A timer the handler starts goes on in that zone. A conversation (`cause.conversation`) is all that followed from one message, and `cause.origin` what it started with (the first message's `{word, by}`), given by the registry from the parent, never claimed: `registry.conversation(id)` (bounded, may forget); spans carry it. What must not be lost is the journal (SPEC §9.3): `registry.journal` tells every call begun and ended, fact said and write in a conversation, as it happens; the host writes it (`parlance_journal`).
- Names are lower-case words split by `.`, joined within by `_` or `-` (`house.door.left_open`, `kitten-daycare.lights`); the first is the vocabulary, a last `vN` the version; never two owners for one name.
- **Who uses a word** (SPEC §6.8): `registry.usesOf(name)` / `usage` count the uses the compiler cannot see (calls by anyone, remote subscriptions, reads by sessions and agents), by the name used; check it before removing an old word or name.
- **Words are a public API.** Plugins, agents and what the host stores name them. Never rename one bare: keep the old name with `host.alias(old, now)` so what named it keeps working.

## Why a call was refused

Stages, first refusal wins (SPEC §9): dedup by id (`idConflict` if the id was given to another call) → command exists → params (`invalidParams`) → callers (`notPermitted`) → `available` (`unavailable`) → guards (`denied`, with the guard id) → handler (`failed`; `timedOut` means *no answer yet*, the work may still finish). `why`/`explain` and the call records (`calls`) tell what happened; `callStarts` and `running` what is in flight.

**Logs and telemetry** (SPEC §9.2): `Registry(log: controller.scope('parlance'))` logs a span per call (a nested call a child span, in one trace; across a connection too), refusals, ticks, the catalog and errors. Spans are kept whatever the level; log lines are by level, their messages constant and what varies in `data`. Without a log nothing is made. In a handler log with `call.span.event(...)` (an event that costs something to build behind `span.isEnabled(level)`; without a log the span is `noop`'s), never a logger found through a zone.

## Remote and agents

- A session's principal is fixed by the host when it accepts the connection: `host.participant(who, vocabularies: [WordSet.open(id)], ...).serve(endpoint)` (a guest's words may come at run time); call ids are per principal. Serve only a participant made for the session: one served already or used in this process is refused. It ends by itself when the connection does (`ended`), the participant going with it; its access by default is the guest's across too (SPEC §14, §22).
- **It is the only way across.** The wire, its client and the mirror are the package's own: a plugin, a phone, an agent each join as a participant. Its feed carries only what its listeners ask for, and what it reads by name (`fetch`), and the host knows what it hears (`session.hears`). `join` completes when its view is live; `settle()` waits for the host. It reads another's state only while it watches it.
- **Delivery** (SPEC §14.1): a state arrives as its value now, a fact at most once (`factsLost` past the retained ticks), a call once per id (`lost` may have run: retry with the id). A fact that must not be lost is a state its owner keeps until it is handled.
- Remote outcomes are data: `CallLost(id)` when the answer did not come back (retry with the id); `synced` false while disconnected.
- MCP tools are curated (`parlanceTools(participant)` in `parlance_mcp`: an agent is a participant, here or across a connection); a host adds its own and must call `McpSession.toolsChanged()` whenever its tools change.

## Rules of the package

- Imports go one way: `remote` and `owners` use `registry`; `participant` uses `registry` and the view interface (`view/view.dart`), never remote; `owners` use `participant` too; only `remote` and `testing` (its connection in memory) use rpc_dart, but for its logger (`package:rpc_dart/logger.dart`), which the registry logs to. Rules between states and commands (when this, call that) are the host's, built on this public API, not the package's. `test/boundaries_test.dart` holds this.
- No words of any domain in `lib/` (the boundary test bans them); the host's vocabulary stays in the host.
- Results are typed (`CallResult<R>`, `Explanation`); serialize at the edges.
- `contract.g.dart` is generated: change `contract.dart`, then `fvm dart run build_runner build`.
- A behavior change updates the contract in `references/` in the same change.

## Testing

- A module of a host is tested with `TestHost` (`package:parlance/testing.dart`, SPEC §24): its own participant, stand-ins for the words of others, what it wrote, said and called read back.
- Fixtures: `test/registry/fixture.dart` (`Fixture`, principals `user`, `agent`, `visitor`, `owner`).
- A whole host in miniature: `example/` (run `fvm dart run example/main.dart`); `test/example_test.dart` holds it to what it prints.
- Time: `fakeAsync(..., initialTime: DateTime(...))` whenever time matters; the registry reads time from its `clock`.
- Name tests after the promise they hold ("an id stands for one call").
- Run: `fvm dart test` in `packages/parlance` (four files at a time, `dart_test.yaml`), or only the files a change touches; `fvm dart analyze`.
