# parlance contract: remote (§14)

Part of the contract the code and its tests follow; sections keep their numbers across these files (`SPEC §n` in the code), and SKILL.md maps them. Where code and contract disagree, the contract is fixed first.

## 14. Remote

Two peer services over one connection (`RpcPeerEndpoint` on both sides), generated by `rpc_dart_generator` from annotated interfaces (`lib/src/remote/contract.dart`); every method has codecs, so they run over any transport. The registry's side serves `Parlance` (`RegistryResponder`); the participant's side serves `ParlanceOwner` (`RemoteOwner`) when its session owns commands.

| Method | Kind | Does |
|---|---|---|
| `describe` | unary | the catalog as the session's principal sees it (`Registry.describeFor`: with what it may call and what cannot run now), and the protocol version |
| `feed(epoch?, since?)` | server stream | the catalog as `describe` gives it, first and on every catalog change; then the feed of §12, as the session's subscription carries it; and after a tick that changes which commands cannot run, the whole set of them (`unavailable`) |
| `subscribe(states?, facts?)` | unary | what the session's feeds carry: these states and facts, or all of them (null); answers the subscription's number |
| `call(id, command, params, override, test, parent?)` | unary | a call on behalf of the session's principal |
| `pushLayer(state, key?, value, priority, ttl?)` | unary | a layer held by the session |
| `popLayer(layer)` | unary | drops a layer of the session |
| `layerEvents` | server stream | what happens to the session's layers |
| `why(state, key?)` | unary | `Registry.explain` as an `Explanation` |
| `layers` | unary | every layer, as `LayerInfo` |
| `recent(fact, count)` | unary | the last facts of a name the registry keeps |
| `define(descriptor)` | unary | a state, a command or a fact of the session's own, as far as the host lets it |
| `undefine(name)` | unary | withdraws a word the session defined |
| `set(state, key?, value, remove, parent?, test)` | unary | writes a state the session owns |
| `emit(fact, payload, id?, by?, parent?, test)` | unary | says a fact the session owns, or an open one it produces; `by` when it speaks for someone |
| `apply(ops)` | unary | what a remote participant asked (§22.4), in order, as one tick: `define`, `undefine`, `set`, `remove`, `emit`, `available`, `kind`, `unkind`, `guard`, `unguard`; an answer per op, a refusal of one not stopping the rest |

`ParlanceOwner`, the participant's side:

| Method | Kind | Does |
|---|---|---|
| `serve(id, command, params, cause)` | unary | serves a call of a command the session owns; answers its value or why it failed |
| `judge(guard, id, command, params, cause, layer)` | unary | asks a guard of the session's about a call of its command; answers why not, or nothing |

- **A session is one connection with one principal**, fixed by the host when it accepts the connection: the host makes a `RegistryResponder(endpoint, registry, principal: …, rights: …)` per connection and `close()`s it when the connection ends. The layers the session pushed and the words it defined go with it; its calls are refused after.
- **A session is a participant** (§22): `describe` tells it its principal and its `namespaces`. **It may own words in its namespaces, as far as the host lets it** (`SessionRights`, the participant's rights): `define` (a further check by descriptor: callers that name viewers), `produce` (which open facts of others it says) and `speakFor` (on whose behalf it says a fact: the fact's cause is theirs, so what links do for it, they do with those rights). Without rights a session only calls and holds layers. A remote owner is an owner like any other: its states have one writer, the session; its commands one handler, the participant's `RemoteOwner`, which the registry calls over the same connection with the call's cause; a handler that throws fails the call with its message, a lost connection fails it too.
- **What a session does follows from what it answers.** `parent` on `call`, `set` and `emit` names a call the session is serving (`RemoteCall.id`) or a fact the registry still keeps (its id): the cause is that message's child, the chain and the test mark carried over, so the journal says why and links see loops. An unknown parent starts a new chain.
- **A call's result is data, not an error.** `done`, `refused` (with the code, the reason, the guard and whether it is overridable), `failed`, `timedOut` travel as the reply, because a refusal is a normal answer and carries more than a status code. rpc_dart statuses are for the session's own errors: `notFound` (no such state, fact or layer), `invalidArgument` (a value or a descriptor of the wrong type), `permissionDenied` (the principal may not set that state, define that word, write a state it does not own, produce that fact or speak for that principal), `alreadyExists` (a name defined already, a state with a setter already), `failedPrecondition` (a state without a setter), `unavailable` (the session ended).
- **A call answers the epoch and seq** the registry had when it answered. A mirror that reached that seq (`RegistryMirror.reach`) shows what the call wrote: a read after a call reads its effect, as it does in the registry's own process.
- **A lost answer is a result, `lost`.** When the connection breaks before the answer, `ParlanceClient.call` answers `CallLost` with the call's id (it always sends one) rather than throwing: whether it ran is unknown, and a retry with the id runs it at most once.
- **Ids are per principal.** The registry sees a call's id, and a fact's, as `<principal>/<id>`: a client that lost its connection retries with the same id and gets the first result; another principal reusing the id does not.
- **`test`** is the only part of a cause a client may set; the chain and the parent are the registry's.
- **Deadlines.** A call has no deadline of the client's: the registry bounds it itself (each hook its timeout, the handler the command's deadline) and answers `timedOut`. The other requests are answered at once and wait the client's `timeout` (10 s).
- **A session's feeds carry what it subscribed to.** Until it subscribes, everything, as before protocol 4. After, a snapshot has only the states it names, a tick only their changes and the facts it names; a tick with nothing of them is not sent, and the next one sent starts right after the last one sent (`from`), so the ticks stay without gaps. Subscribing again replaces it: each open feed gets a `values` item with the values of the states it carries now and did not, and which it carries (`keep`), so a copy drops the others; that item and the snapshots after carry the subscription's number, so a participant knows when its feed follows it. The subscription is the session's, and so is what the host knows from it: `RegistryResponder.hears(test)` (whether its feeds carry a fact that matches, or it read the recent of one), for what a participant learns of viewers.
- **A word's `readers` (§6.1, §6.3) bound what a session sees of it.** A state it may not read is left out of its snapshots, ticks (the next tick sent still starts right after the last one sent), `values` items and the layers it is told; a fact it may not hear, out of its ticks; `subscribe` naming either, `why` of the state and `recent` of the fact answer `permissionDenied`, and such a fact is no `parent` of what it does.
- **Word status over remote** (§6.5). The feed's catalog says what the session's principal may call and read and which commands cannot run; an `unavailable` item follows a tick that changes the latter, whether or not the tick itself is sent. The mirror answers `statusOf(name)` from them and tells `statusChanges` when either moves; while cut off it answers what it had last. Protocol 5: a client skips a feed item of a kind it does not know. Protocol 6: `apply`, `judge`, and `describe` with the principal and namespaces. Protocol 7: an op of `apply` and a `call` may carry `as`, a part of the session's principal (§22.3); the host acts as that part, and refuses anything else; a part's guard is known as `<part>/<id>`.
- **The mirror** (`RegistryMirror`) keeps a participant's copy of the states from the feed and, given a new client after a lost connection, resumes after the seq it has; a gap sends it back to a snapshot. `synced` is whether it follows the registry now: false when its feed is lost, true again with a snapshot, or at once when the feed resumes in the same epoch (nothing may have happened since). `subscribe(states, facts)` keeps only those (waiting until its feed has their values) and subscribes a new connection again before its feed; then its seq moves only with the ticks it carries, so `reach` does not wait for a write it does not keep. It keeps no facts: `recent` asks the registry, so the answer is the same here and there.
